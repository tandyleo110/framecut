# framecut

帧精确视频切片工具。拖入视频，按帧号切出片段，逐位无损。

拖视频进网页 → 抽帧看缩略图 → 填帧号 → 出片。全程本地跑，浏览器只是个界面。

![界面](https://img.shields.io/badge/Node-%3E%3D18-5FA04E) ![依赖](https://img.shields.io/badge/依赖-ffmpeg%20%2B%20ffprobe-5FA04E)

## 环境要求

**必装，缺一不可：**

| 依赖 | 版本 | 说明 |
|---|---|---|
| [Node.js](https://nodejs.org/) | ≥ 18 | 跑后端脚本 |
| [ffmpeg](https://ffmpeg.org/download.html) | ≥ 6.0 | 抽帧和切片都靠它 |
| ffprobe | ≥ 6.0 | **切片功能必需**，ffmpeg 完整包里自带 |

ffmpeg 和 ffprobe 都得在 `PATH` 里（命令行敲 `ffmpeg -version` 能出版本号）。
只装 ffmpeg 不装 ffprobe 的话，切帧能用，切片段会报错。

**装完验证：**

```bash
node --version
ffmpeg -version
ffprobe -version
```

三条都能出版本号再往下走。

### 不想配 PATH？

把 `ffmpeg.exe` 和 `ffprobe.exe` 直接丢到脚本同目录，脚本会优先用它们。
版本必须是同一批的，别混。

### Windows 装 ffmpeg

从 [gyan.dev](https://www.gyan.dev/ffmpeg/builds/) 下 `essentials` 或 `full` 的 zip，解压后把 `bin` 目录加进系统 PATH。GitHub 上 [BtbN/FFmpeg-Builds](https://github.com/BtbN/FFmpeg-Builds/releases) 也有。

## 跑起来

```bash
git clone git@github.com:tandyleo110/framecut.git
cd framecut
node app.js
```

浏览器会自动打开 http://127.0.0.1:8765 。端口被占用就自动往后顺延（8766、8767…），控制台会打印实际地址。

没有依赖安装步骤，也没有 `package.json`，纯 Node 内置模块 + 系统 ffmpeg。

## 怎么用

### 抽帧

1. 把视频拖进网页
2. 选抽帧密度：`0` = 原视频全部帧，或者每秒几张（也可以直接填数字）
3. 选格式 png / jpg
4. 点「开始切帧」

产物在 `cut-data/<视频名>/00001.png ...`，编号从 1 开始。

### 切片段

1. 在缩略图上找到要的那一帧，记下图下面那个数字
2. 填「起始帧」和「结束帧」，起止都含
3. 选画质（见下）
4. 点「开始切片段」

产物在**脚本同目录**，命名 `<视频名>_<起帧>-<止帧>.mp4`。比如填 97 和 263，得到 `cut_97-263.mp4`。

切完可以接着切别的片段，不用重新上传。换视频时临时文件自动清理。

## 画质两档

| | 画质 | 体积（167 帧 4K 竖屏实测） | 原理 |
|---|---|---|---|
| **逐位无损**（默认） | 解码像素与源**逐位相同** | 174.6 MiB | x265 `lossless=1` |
| **视觉无损 CRF 12** | 肉眼分辨不出 | 19.3 MiB | `-crf 12`，专业后期通用档 |

两档的**帧精确性完全一样**，都是严格按帧号切。体积和画质的取舍跟帧号无关。

crf 档文件名会带 `_crf` 后缀（`cut_97-263_crf.mp4`），两档并存不会互相覆盖。

### 编码器跟随源视频

不可切换。源是 HEVC 就出 HEVC，源是 H.264 就出 H.264。

色彩元数据（bt709 等）、像素格式、音频采样率和声道数全部照抄源文件，播放器不会偏色。

---

## 为什么必须重编码

关键帧稀疏的视频**没法用流拷贝做帧精确剪辑**。

HEVC 的关键帧可能隔 2 秒才一个，而 `-c copy` 只能切在关键帧上。你要的那一帧通常不在关键帧位置，`-ss` 会回退到上一个关键帧，首帧就错位半秒以上。

所以只能重编码。既然重编码，无损就意味着**用原编码器的 lossless 模式**，解码像素与源按位相同。

**如果你能接受关键帧级别的误差**，那用任何剪辑软件直接剪更快，不需要这个工具。

### 一个容易踩的坑

**x265 的 `-qp 0` 不是无损。**

`-qp 0` 只让量化器归零，但 x265 内部色彩转换的舍入误差还在。实测逐帧 md5 比对：

```
x265 -qp 0          ✗ 像素 md5 对不上
x265 lossless=1     ✓ 逐位相同
x264 -qp 0          ✓ 逐位相同（x264 的 qp 0 本来就是无损）
```

本工具用的是 `lossless=1`，不是 `-qp 0`。

---

## VFR 视频也能正确切

源视频可能是可变帧率（VFR），相邻帧间隔不均匀。实测遇到过帧间隔只有 2.984ms 的情况（正常 16.7ms）。

**按时间定位（`-ss`）在 VFR 上会偏一帧**，所以本工具走 `select='between(n,a,b)'` 按帧号挑，完全绕开时间戳。

代价是从头解码到尾，比 `-ss` 慢。但帧精确没有捷径。

切完会用 `ffprobe -count_frames` 复核帧数，对不上就报错并删掉文件，不会给你一个错位的结果。

## 项目结构

```
framecut/
├── app.js        后端：HTTP 服务 + ffmpeg 调用
├── index.html    前端页面（改样式直接改这个，刷新浏览器生效）
└── cut-data/     抽帧产物（自动生成，已 gitignore）
```

页面和后端分开的。启动时读一次 `index.html` 缓存住，改页面不用重启服务。

**产物**：
- 抽帧 → `cut-data/<视频名>/00001.png`
- 切片 → `<视频名>_<起帧>-<止帧>.mp4`（脚本同目录）

**临时上传**放在系统临时目录的 `vcut-tmp/`，用完自动删。

---

## 支持的格式

`mp4` `mov` `mkv` `avi` `webm` `flv` `wmv` `m4v` `mpg` `mpeg` `ts` `3gp`

切片段时源视频的编码需要有对应的无损编码器（HEVC / H.264 / VP9）。其他编码会明确报错，让你先转成 HEVC 或 H.264，不会偷偷降画质。

## 隐私

视频不会离开你的机器。上传只是把文件交给同机上的 ffmpeg 处理，产物也写在本地。没有网络请求，没有账号，没有遥测。
